Umskipti í Framkvæmd

  • Hönnunarsprettinum er lokið (að mestu).
  • Ef hönnunin er 80% tilbúin, byrjið að forrita.
  • Ekki festast í "Pixel Perfection" pælingum.
  • Markmiðið breytist úr "Hvað ef?" í "Hvernig?".

Vinnuflæði: Git Flow

Gullna reglan: Aldrei committa beint á main.

  • Greinar (Branches): Búið til grein fyrir hvert verkefni.
    feature/login-page, fix/navbar-typo
  • Pull Requests (PRs): Hjarta samvinnunnar.
  • Yfirferð kóða (Code Reviews): Ekki bara smella á "Merge". Lesið hann. Prófið hann. Spyrjið spurninga.

Hópavinnubrögð

  • Daglegir fundir (Standups): 5 mínútur hámark. "Hvað gerði ég? Hvað ætla ég að gera? Hindranir?"
  • Parforritun: Tveir heilar, eitt lyklaborð. Leysir erfið vandamál hraðar.
  • Staðlar: Komið ykkur saman um nafngiftir (camelCase?), formatting (Prettier?) og skráaskipulag áður en þið byrjið.

Framendi

  • Uppbygging: HTML/Component
  • Stíll: CSS / Tailwind / eitthvað annað. Látið það passa við Figma.
  • Virkni: JavaScript / React / Next.js / eitthvað annað.
  • Notendaupplifun (UX): Mjúk samskipti.

Bakendi

  • Gagnagrunnur: Hönnun skema & uppsetning.
  • API: RESTful endapunktar / Gagnaumsýsla, allar CRUD aðgerðir
  • Leiðarkerfi (Routing): Dýnamískar síður/leiðir.
  • Virkni: Sértækar aðgerðir (t.d. Auðkenning, Leit).

Markmið: MVP (Vika 5)

Markmið vikunnar: Minnsta nothæfa vara (MVP) tilbúin.

  • Verkefni 4: Grunnvirkni vefsins þarf að vera komin upp.
  • Skilafrestur: 1. febrúar.
  • Áhersla: Ekki búa til allt, bara það sem skiptir máli fyrir kjarnann.

Framúrskarandi
Snyrtilegur kóði Enginn inndráttur, mjög ólæsilegur kóði. Ósamræmi í inndrætti, dauður kóði til staðar. Sæmilegur inndráttur en vantar samræmi í stíl. Vel uppsettur kóði, fylgir flestum venjum. Fagleg uppsetning, fullkominn inndráttur og enginn óþarfi.
Góð breytuheiti Breytuheiti (x, y) segja ekkert til um innihald. Bland í poka, sum heiti óskiljanleg eða á íslensku. Flest heiti skiljanleg en vantar samræmi (camelCase). Lýsandi heiti og góð beiting á nafngiftareglum. Öll heiti lýsandi, á ensku og fylgja ströngum stöðlum.
Branches og Commits Allt unnið beint á main, engin commit skilaboð. Fá commits, stór og ómarkviss. Notar branches en commits eru stundum óljós. Góð notkun á branches, regluleg commits. Atomic commits, feature branches, skýr skilaboð, PR notað.
Kóðarýni (Reviews) Engin virkni í Code Reviews. Mjög sjaldgæf eða "LGTM" án athugasemda. Einhver rýni en vantar dýpt í endurgjöf. Regluleg rýni með góðum ábendingum. Ítarleg, uppbyggileg rýni eftir hvern tíma á öllum PR.
Hönnun og útlit Vefur brotinn, virkar ekki eða mjög ljótur. Erfiður í notkun, stíl vantar víða. Virkar og lítur sæmilega út, smá gallar. Fallegt útlit, góð notendaupplifun (UX). Faglegt, responsive hönnun og framúrskarandi UX.
Kynning Óundirbúin, vantar efni eða mætingu. Lestur beint af glærum, óörugg flutningur. Sæmileg kynning, koma efni til skila. Góð og skýr kynning, allir taka þátt. Fagleg, örugg, lifandi og sannfærandi kynning.
Nýting á CRUD aðgerðum Engar CRUD aðgerðir virka. Aðeins Read virkar, aðrar bilaðar. Flestar aðgerðir virka en eru óstöðugar. Allar CRUD aðgerðir virka rétt. CRUD útfært fullkomlega með villumeðhöndlun og öryggi.
Uppsetning gagnagrunns Enginn gagnagrunnur eða tenging. Gagnagrunnur settur upp en illa hannaður. Grunnur virkar, einföld skema hönnun. Vel hannað skema, eðlileg tengsl og gagnatög. Best practices í hönnun, indexes, seed data og skölun.
Tenging við framenda Engin tenging, bara harðkóðuð gögn. Tenging oft biluð eða mjög hæg. Gögn birtast en uppfærslur sjást ekki strax. Góð tenging, gögn flæða vel. Óaðfinnanleg samþætting, loading states og error handling.
